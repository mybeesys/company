# My Bee Cashier (Flutter) — فاتورة إتلاف المخزون

> **الغرض:** ملف لمطوّر Flutter الكاشير. قيد الإتلاف يُرحَّل على السيرفر.  
> **التاريخ:** 2026-10-22  
> **النطاق:** مستند إتلاف (ليس مبيعات) + ترحيل قيد محاسبي. لا تغيّر مسار فاتورة البيع العادي.

---

## ماذا يفعل السيرفر؟

عند حفظ فاتورة إتلاف (حالة نهائية، ليست مسودة):

| سياسة الجرد | مدين (+) | دائن (-) |
|--------------|----------|----------|
| الجرد المستمر | مصروف إتلاف مخزون `waste_expense` | أصل المخزون `perpetual_inventory_asset` |
| الجرد الدوري | مصروف إتلاف مخزون `waste_expense` | المشتريات `purchases_purchase` |

المبلغ = **تكلفة المخزون** (متوسط / FIFO / LIFO). لا إيراد، لا ضريبة، لا خصم، لا طرق دفع.

---

## كيف ترسل فاتورة إتلاف؟

نفس مسار المصروف الداخلي، مع أحد الخيارين:

### أ) نوع مصروف إتلاف

`POST /api/stor-sales-invoice`

- `purpose`: `internal_consumption` **أو** `waste`
- `internal_consumption_type_id`: نوع اسمه إتلاف / هدر / waste / spoilage (من `GET /api/internal-consumption-types`)
- أصناف + `establishment_id`
- **بدون** `payments` وبدون خصم/ضريبة

السيرفر يكتشف النوع من الاسم أو `type_key` ويوجّه القيد إلى `waste_expense` وليس حساب وجبات العاملين.

### ب) غرض إتلاف صريح

```json
{
  "purpose": "waste",
  "establishment_id": 1,
  "status": "final",
  "items": [ { "product_id": 86, "quantity": 1 } ]
}
```

`purpose=waste` مسموح بدون نوع إذا لم تختر نوعاً من القائمة. الأسعار تُعاد كتابتها بتكلفة المخزون على السيرفر.

---

## لا تخلط مع

| المستند | `purpose` | القيد |
|---------|-----------|--------|
| بيع عادي | `standard` | إيراد + ضريبة + تحصيل + COGS |
| مصروف داخلي (وجبات/ضيافة) | `internal_consumption` + نوع غير إتلاف | مدين حساب **النوع** |
| إتلاف | `waste` أو نوع إتلاف | مدين **waste_expense** |

وجبات عاملين تبقى على حساب النوع. الإتلاف فقط على مصروف الإتلاف.

---

## أخطاء `422`

| `code` | المعنى |
|--------|--------|
| `waste_journal_failed` | تعذّر ترحيل قيد الإتلاف — اعرض `message` |
| `internal_consumption_type_required` | مصروف داخلي بدون نوع (وليس `purpose=waste`) |

اعرض `message` كما يرجعها السيرفر.
